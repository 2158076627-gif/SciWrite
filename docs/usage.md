# 使用 SciWrite

在 Codex 任务开头写 `$write-technical-plans`，随后给出研究问题、已有资料和交付要求。技能会围绕“问题—证据—方法—实施—验证”组织内容，并按文种调整章节。

## 先提供这些信息

| 输入 | 建议说明 |
| --- | --- |
| 研究问题 | 研究对象、具体难点、已有认识、想验证的判断 |
| 已有条件 | 设备型号、可用数据、人员、时间、预算及已完成工作 |
| 资料 | 原稿、论文全文或 DOI、数据来源、官方手册、已有图表 |
| 面向谁写 | 项目评审、导师、合作者或论文读者；项目指南与模板要求 |
| 交付要求 | 文种、篇幅、语言、Word / PDF / 纯文字、截止时间及输出位置 |

缺少资料时也可以开始，但应明确检索范围和待补信息。将“已测得”“官方标称”“文献报道”“本项目拟采用”和“待验证目标”写清楚，有助于避免把规划误当成结果。

## 四个可复制的任务提示

方括号中的内容换成你的课题信息，并附上相关文件。安装步骤见 [安装指南](installation.md)。

### 1. 起草科研项目计划书

```text
$write-technical-plans
根据附件资料撰写[研究主题]的科研项目计划书，面向[目标读者]，篇幅约[字数或页数]，输出可编辑 Word。
核心问题是[问题]，已有条件是[设备、数据、团队与时间]。
请说明路线选择、方案比较、实施步骤、阶段产物、进入下一阶段的条件、对照设计和失败判据。
把来源事实、项目现状、建议方案与规划数值分开表述；未确定的预算、工期和性能目标标为假设或待验证目标。
采用三线表，完成后渲染并逐页检查。
```

适合从研究设想和零散资料形成可继续修改的完整计划。对于已有项目指南，先附指南，再明确需要遵守的章节、字数与格式。

### 2. 组织论文综述与研究现状

```text
$write-technical-plans
为[研究主题]撰写论文综述，范围是[研究对象、时间范围与方法分支]，面向[目标读者]。
优先使用附件论文；需要补充时检索原作者、出版方或官方来源，记录来源链接和核查日期。
按关键问题或机制组织，比较方法差异、适用条件、评价设计与证据边界，解释研究空缺。
区分原研究结论与综述的综合判断；不补造引文。文献不足时说明覆盖范围和待补方向。
```

适合梳理方法关系和证据边界。它不会将逐篇摘要的拼接当作综述，也不会用未经阅读核对的引文填补空缺。

### 3. 修改研究方案与技术路线

```text
$write-technical-plans
修改附件[研究方案文件]，保留我的有效观点、专业术语和已有研究条件。
补足“问题—方法—验证”的关系，压缩重复和套话，明确每个技术模块的输入、输出、依赖与验证。
重点模块优先安排2–3张相关且互补的真实期刊原图；设备结构和接口可用确切型号的官方手册图。
逐图核对原文件、图号或子图、页码、来源和复用条件，并在相邻正文解释具体信息、本项目借鉴与适用边界。
若没有合适可用原图，标明缺项并继续完成方案；不凑图，不将文献结果归为本项目实测。
```

2–3 张是重点模块的优先目标，相关性和可核验性优先于数量。技术路线中的箭头与模块关系，应能在正文中找到对应的输入、输出和成立条件。

### 4. 仅统一已有 Word 排版

```text
$write-technical-plans
将附件[draft.docx]按技能默认样式整理，输出为[final.docx]。
保留文字、图片、字段、链接、引用、合并单元格与编号；本次只调整格式。
所有内容表格使用白底黑字三线表，不加竖线、网格或灰色表头。
格式处理前后比对文本，并渲染逐页检查缩进、跨页表头、图与题注、裁切和异常空白。
如果当前环境无法渲染，说明未完成视觉验收的部分。
```

默认采用宋体正文 12 磅、黑体标题、英文与数字 Times New Roman，正文 1.35 倍行距、两字符首行缩进。参数来自 [`assets/style.json`](../write-technical-plans/assets/style.json)；脚本使用方式见 [安装指南](installation.md#word-排版脚本的依赖)。列宽、分页和图像布局仍需要视觉判断。

## 核验事实与表达规划

来源核验回答“材料是否真实、当前有效、确实支持这个说法”；方案规划回答“在给定条件下准备怎么做”。两者应分别交代：

| 内容性质 | 应怎么写 |
| --- | --- |
| 文献或官方事实 | 标明原来源；核对发表状态、版本、型号、单位和适用条件 |
| 本项目已有结果 | 提供实测数据、评价过程和统计依据 |
| 建议路线 | 解释选择依据、替代方案和适用边界 |
| 工期、规模、预算和效果目标 | 标为规划值或假设，写明计算依据与验证方式 |
| 尚未核验的材料 | 明确未核验项及影响，不据此作确定结论 |

仓库展示样例用于说明工作方式与文稿形态，**不是性能基准、真实实验结果或效果提升证明**。减少模板化表达，是通过具体问题、证据和因果解释改善行文；不承诺 AI 检测分数或投稿等级。

## 成稿检查清单

- [ ] 核心问题、路线选择、交付物和成立边界能被独立读者理解。
- [ ] 关键判断有来源或假设标记，文献结论、官方参数、规划与实测分开。
- [ ] 对照、数据划分、指标、失败判据和风险调整与研究目标对应。
- [ ] 阶段有具体动作、产物和进入条件，工作量与工期计算写明假设。
- [ ] 内容表格白底黑字三线；文字、单位、表头与跨页重复表头可读。
- [ ] 插图来源、图号、子图与使用条件清楚，正文逐图解释且不误归属结果。
- [ ] Word 已渲染并逐页检查；无法检查的部分已如实说明。
- [ ] 最终文件可编辑、可打开，引用与链接保留，个人或敏感信息已按任务要求处理。

临时格式要求直接写在本次提示中；长期规则应同步修改对应配置和参考文档。研究判断、引用和最终稿仍需作者核查。
