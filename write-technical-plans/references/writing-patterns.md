# 内容结构与段落写法

采用简洁、具体、可复核的科研行文。用普通词解释技术关系；由字体层级、留白和规范表格形成学术外观。文档首要用途是让读者能判断方案并开始执行。

## 章节职责

按信息量选择并合并以下模块。研究型计划书保留近邻文献、可证伪假设和统计设计；工程实施方案可将其改为现有方案比较、验收指标及工况覆盖。

| 模块 | 应回答的问题 | 适宜的呈现方式 |
|---|---|---|
| 开篇与边界 | 解决什么问题，选什么路线，做到什么程度 | 1至2个连贯段落；必要时附本期交付表 |
| 前提与目标 | 已知什么、未知什么，哪些条件影响决策 | 正文解释边界；简表列关键条件 |
| 取舍与证据 | 为何选这条主线，现有方案的差距是什么 | 有来源的分析；同条件比较表 |
| 方法及假设 | 输入、机制、输出、适用条件，怎样证伪 | 逐层正文；有意义的公式或技术图 |
| 资源及接口 | 设备、软件、代码、数据各负责什么 | 对象—作用—接入/验收条件三线表 |
| 实施及记录 | 逐次做什么，保留哪些产物，如何追溯 | 可执行段落或必要的步骤列表 |
| 验证设计 | 哪项主张由哪种对照和指标支持 | 对照关系三线表、指标三线表与统计正文 |
| 阶段计划 | 何时做什么，交付什么，进入下一阶段的条件 | 阶段—规划时间—交付与进入条件三线表；按需独立甘特图 |
| 近期行动与调整 | 从哪里开始，什么情况下缩小或替换路线 | 具体动作；风险—触发条件—调整表 |
| 来源入口 | 事实来自哪里，何时核查，哪些仍待核实 | 编号参考文献与可复核入口 |

参考样例中的设备型号、接口、预算、数据量和周期属于原项目条件。新方案先取得本项目证据，再确定这些值。为其他领域写作时保留“定义样本单位、隔离开发与评价、记录版本”等原则，用本领域术语实现。论文综述与技术路线按 `review-and-routes.md` 调整章节职责，不强行套入计划书的预算和时间模块。

## 三种段落模式

根据段落的职责选择一种模式，灵活调整句数与长度，不机械重复相同句式。

**判断与论证：结论 → 依据 → 影响 → 成立边界。** 先写为何选，再写支持它的证据，最后说明什么条件会改变判断。将事实和主观建议分句表达，必要限定紧接对应主张。

**机制与接口：输入 → 处理 → 输出 → 启用条件。** 解释各数据或组件负责什么、如何变换或协同、产出交给谁。模型名称、工具名称和公式随后说明其用途与适用范围。

**执行与验收：动作 → 保存产物 → 验收 → 不满足时的调整。** 使用登记、读取、核对、比较、标定、冻结等可执行动词。计划数值注明规划性质，说明改变它的关键变量。

示例（通用写法，非实测结论）：

> 本期优先验证跨批次缺陷识别。已有图像能够支持离线对照，但标注一致性尚未核实，因此先确认主要误差来源，再决定是否扩大模型。阶段成果以独立批次上的召回率、误报率和复核时间衡量。
>
> 系统读取图像、批次标识与缺陷标签，先统一字段含义并标记缺失记录，再提取特征并输出缺陷位置与置信度。阈值在开发批次上确定，评价批次保持独立；缺少必要标签的记录先进入质检流程。
>
> 第一阶段完成数据清单、标注规范及两条真实记录的全流程验证，保存转换日志与质检报告。数据来源可追溯且关键字段通过核验后，进入批量评测；若条件未满足，先补标注或修订输入协议，再调整阶段时间。

## 表格与叙述的分工

正文承担因果、方法解释、证据判断和较长的边界说明。表格承担同类项对照和任务对应关系，通常3至4列；按内容安排列宽，短字段窄、解释字段宽。连续长表逐项检查是否真的需要比较，避免把段落逐行搬入表格。

表题简洁、与表同页；单位写在列名或数值旁。规划金额、时间和样本量写明假设与依据。只有一条关系且一句话可讲清时，使用正文。图只为说明必要关系服务，精确图表使用可复核绘制工具。

全部内容表格统一使用三线表，包括设备、接口、实施任务、预算、方法比较、验证、风险和阶段计划；不混用网格、竖线、矩阵色块或进度色块表格。所谓“矩阵”只指方法×条件、传感器×功能或消融组等比较结构，仍用三线表排版。时间信息在三线表中用阶段、日期或区间文字表达，确有需要时另绘甘特图或进度图，不用色块网格表代替。三线表参数与脚本标记见 `tables-and-charts.md`。

采用本技能默认的字体、纯黑文字和正文两字符首行缩进，不为配图扩展重新设计文档样式。原创路线图用于说明本项目机制与依赖；论文原图用于展示已有研究的对象、平台、方法或结果；官方设备资料原图用于说明已核实型号的规格、尺寸、接口或标定条件。分别标注身份，原始图片不能改写成本项目结果。

## 文献图片与段落衔接

按重要章节或研究模块提前规划配图，每个重点内容优先安排2–3张合适的真实原图；普通段落和所有小节不逐一配额。核心机制、平台布置、接触过程和结果论证优先选择顶刊论文原图，以方法或机理、平台或过程、结果等互补证据支撑主张。相关性与原文核验优先，期刊级别不代替证据质量。一个原图的多个子图仍算一张，不能通过分拆、重复或无关图凑数量。

设备选型、接口和标定模块可补充制造商官方数据手册中的实物、尺寸、连接或标定曲线原图，并与相关论文图组合计入该模块配图。核对完整型号、配置、文档编号、修订版本、条件和复用依据；厂家标称、厂家测得或典型值与本项目实测分开表达。设备图不能替代研究方法或实验效果的论文证据，需要顶刊论证的核心模块优先论文图。检索、来源登记、题注、引用和复用规则见 `literature-figures.md`。

每张图按“图前引入目的 → 紧邻关联段落的原图与可追溯题注 → 按图号和必要子图的正文解读 → 本项目映射与边界”组织。解读先描述图上可观察的信息，再陈述原作者或官方资料在什么对象、型号和条件下给出什么结论或参数；随后解释本项目可借鉴的机制、安装、接口或评价方法，以及需要怎样的对照或标定确认其适用性。多图联合支撑重点内容时逐图交代各自作用，不能只写“如图所示”、只有图注没有正文，或把图集中堆在附录。避免逐项复述整幅图例而未回答段落问题。

只有查阅原文或官方原文件与对应图后才能写图号、子图含义、数值及因果解释。原论文的效果不能改写成自己的预期保证；当对象、传感器、尺度或接触条件不一致时，写明迁移需要验证的变量。不同论文的研究结果只有在任务、数据、指标和实验条件可比时才作直接比较；否则分别说明证据作用。没有合适且可复用原图时说明实际数量、缺项与待补条件，继续交付其他部分；明确标注的原创示意不能作为满足2–3张真实原图要求的替代。

## 学术表达与证据

以对象、动作和结果组织句子，避免空泛的“全面赋能”“打造体系”“突破瓶颈”等无可验证表述。段落具有自然变化；必要边界用正向条件说明，错误前提需要纠正时直接说明依据与风险。

把方法设想称为假设或建议，把工作安排称为规划，把已有成绩对应到实际证据。示范文字的语气和结构可以延续，设备事实、文献结论、实验数字和效果不得迁移为新项目事实。

现有条件不明时，写出其对路线和验收的影响。为关键成本、样本偏差、标注成本、资源竞争、失败记录与返工留出分析位置。明确阶段进入条件及可执行调整，效果与发表结果保持待验证性质。

## 减少模板化表达的修订方式

先确认段落中的有效判断，再检查研究对象、证据、因果关系与边界是否完整。作者已给出的具体观察、术语和取舍尽量保留；只有事实错误、逻辑冲突或表意不清时修订。缺少资料时指出需要补充的内容，不用虚构实验、经历或引文填满段落。

删去不承担论证作用的开场与结尾，压缩连续出现的“首先、其次、最后”“意义重大”“显著提升”等套话。过渡句说明真实关系，例如前项暴露什么问题、后项如何解决，而不靠“此外”“综上所述”串接无关内容。关键词保持稳定，不为追求变化反复更换专业术语。

按信息难度安排句子长短与段落长度，不强制每段相同句数、相同小标题或排比结构。一个句子集中解释一组紧密相关的信息；长句涉及多重假设时拆分。已经用来源支持的判断可以直接表达，不给每句都加空泛保留语。

例如，将“本研究将构建高效智能体系，全面提升系统性能”改成“本研究先识别跨批次误差的主要来源，再比较特征校正与重新标注的成本；是否采用校正由独立批次上的误报率和复核时间决定”。后句仍是方案设计，不能伪装为已取得结果。

完成后逐段检查：换一个课题名后仍完全成立的内容是否应删改；关键判断能否找到来源或具体研究条件；段落是否解释了为何这样做。目标是使文字更自然、具体、便于审阅，不以故意写错、打乱逻辑或机械改词模拟作者风格，不承诺通过 AI 检测。
