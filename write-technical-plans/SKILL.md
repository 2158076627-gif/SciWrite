# 科研项目书与计划书撰写

使用统一的学术排版与论证方式，辅助科研项目计划书、研究方案、论文综述和技术路线写作。把一个主要问题落实为证据、方法、资源、可执行步骤和验证条件；根据文种与研究规模决定章节与篇幅。用具体研究对象、来源证据和因果解释减少套话及模板化表达。

## 读取规则

1. 先读 [排版参数](assets/style.json) 和 [内容及段落写法](references/writing-patterns.md)。排版参数是可修改的唯一数值配置，正文写法从参考文档提炼。
   有表格、技术图、统计图或阶段计划时，读取 [图表选择与表格标记](references/tables-and-charts.md)；解释方法、机制、实验平台、文献结果或设备选型与接口时，读取 [真实来源配图与解读](references/literature-figures.md)。
2. 写论文综述、研究现状或技术路线时，读取 [综述与技术路线](references/review-and-routes.md)，按该文种组织证据。若 `assets/reference.docx` 存在，可用于核对版式和语气；分享版不含个人项目样稿，缺少该文件时直接使用排版配置与写作参考。新项目的设备、预算、数据规模、方法、文献及结果根据新证据填写。
3. 用户本次明确要求优先于技能默认值。制作 Word 时优先采用当前环境的 documents 技能；不可用时按 [独立运行与 Word 检查](references/portable-docx.md) 完成。研究决策采用本领域专业资料或可用的领域技能，不依赖特定用户的研究技能。

## 写作流程

1. 核查问题的错误前提、逻辑跳跃、信息缺失和现有约束。把现有事实、来源事实、方案建议、规划数值、可检验假设分开表述。已有信息足够时直接推进；只为阻断关键决策的缺失信息提问。
2. 开篇直接交代核心问题、选定路线、预期交付和成立边界。确定一条主线，为支撑模块、可选项和后续工作分配清楚的职责。
3. 按项目需要组织“问题与定位—证据与方案比较—方法及假设—资源与接口—实施与数据协议—验证与统计—阶段计划及调整—来源”。合并无独立作用的章节；使用参考文档中的章节职责，而非固定复刻13章或18页。
4. 用连贯段落解释依据、机制、因果和适用条件。每段围绕一个判断或步骤，按参考中的三种段落模式选择写法。把术语、软件、算法和参数紧接其用途说明。
   修订时保留作者已提供的有效观点、术语和研究条件，补足推理与证据，再删去重复铺陈。减少机械化表达不靠同义词替换、故意写错或虚构经历；不承诺任何 AI 检测分数。
5. 全部内容表格采用本技能默认的三线表：白底、黑字，仅顶线、表头下线、底线，不加竖线、单元格网格或灰色表头。设备、接口、任务、预算、指标、文献比较、方法×工况矩阵和阶段计划均遵循此格式；矩阵仅指比较结构。需要直观时间轴时另绘甘特图，表格仍为三线表。把较长的推理放在正文；表中保留读者需要逐项比较的字段。
6. 给核心主张安排公平对照、独立评价、数据划分、指标与失败判据。给阶段安排动作、产物和进入条件；将工作量计算的假设写明，工期和效果以规划或待验证目标表达。
7. 核实动态数字、代码、数据、许可证、论文发表状态与软件兼容性，优先使用原作者、出版方或官方资料。记录来源和核查日期。参考文档中的旧链接和数值仅作写作示例。项目内部未测数值明确其性质，效果提升和投稿档次由实际证据支持。
8. 为每个重点研究内容或重要技术模块规划2–3张互补、相关且可核验的原图，提高本领域顶刊或高水平期刊原图的覆盖；优先组合方法或机理、平台或过程、结果或对照证据。设备选型、结构、接口与标定说明可配确切型号的官方数据手册或技术手册图片。核对原文件、图号、子图、页码及复用条件后，把图放在对应论证附近；正文按图号解释图中具体信息、本项目借鉴和适用边界，不能只写图注或集中堆图。2–3张是重点模块的优先目标，不是每个小节的硬配额；不以拆分子图、重复用图或无关图片凑数。只把文献结果归于原研究，设备标称参数和本项目实测分开；没有合适可用原图时说明缺项并继续完成其余内容。

## 应用排版

用 Word 的 Title、Subtitle、Heading 1–3、Normal 等语义样式区分内容；为元信息、参考文献分别采用 `PlanMetadata`、`PlanReference` 样式。表题采用 `PlanTableCaption`（置表上），图题采用 `PlanFigureCaption`（置图下）；这两个段落样式须先创建，均继承 Caption，脚本按其名称处理。正文用真实首行缩进，避免通过空格制造缩进。

完成草稿后运行：

```bash
python <本技能目录>/scripts/apply_style.py draft.docx --output final.docx
```

脚本读取 `assets/style.json`，统一中英文字体、纯黑文字、字号、两字符缩进与页边距，把所有内容表格转换为三线表；保留正文、字段、链接、图片、合并单元格、表格列宽及编号。正文首行缩进按“正文磅数 × 缩进字符数”计算，字体变大时仍保持两字符。执行环境有主运行时要求时，使用该环境指定的 Python。

新建内容表格用 `scripts/apply_style.py` 的 `mark_table(table, "three_line", header_rows=1)` 标记，多行表头传实际行数。默认配置的 `force_content_three_line=true` 会覆盖旧网格、矩阵、进度与保留样式标记，清除其竖线、网格和底色。只有无正文文字的并排图片布局可用 `plain` 和零表头，不能以此绕过内容表格规则；兼容接口的详情见图表参考。只有图片的段落不作正文缩进。

新绘图的文字按中英字体规范设置，颜色使用克制且可区分的配色；图例、单位、误差表示必须可读。引入论文原图时保留其文字、颜色、单位和色标，只调整插入尺寸及外部题注，避免改动导致证据失真。

单次改变排版时，将配置复制到工作区的临时 JSON，修改所需值并加 `--profile temporary-style.json` 运行；只有用户明确要求本次采用其他表格样式时，才在临时配置关闭 `force_content_three_line` 并设置相应样式。长期偏好再更新本技能默认配置。列出排版参数时分别读取封面标题和章节标题字段，避免混用其行距与间距。

标题、表内文字、题注、列表、页眉页脚、元信息和参考文献采用各自规则；普通正文采用首行缩进。引用与元信息最好显式指定上述样式，避免仅依赖文本识别。仅应用格式的任务先后比对全文，确保内容未改。

## 交付检查

- 核对正文、表头、表内、链接和页眉页脚文字均按黑色规则显示；中文使用宋体或标题黑体，英文及数字使用 Times New Roman。
- 按 documents 流程或独立运行参考渲染并逐页看图，确认正文缩进、可读字号、所有内容表格白底三线且无竖线或网格、多行及跨页重复表头完整、图与题注相邻；检查拥挤、裁切、异常空白和孤立标题。表格列宽与分页仍需人工判断，脚本不能代替视觉验收；没有渲染条件时如实说明尚未完成视觉检查。
- 核对重点模块的配图覆盖及2–3张目标的合理性；逐图核对论文或官方设备文件身份、发表状态或型号版本、图号和子图、来源链接、复用条件，以及相邻正文对该图具体内容的引用和解释。原图、文献重绘示意图、本项目规划图和实测结果图明确区分；检查标签与结论是否被误改、夸大或误归属。
- 核对每项关键判断有依据或假设标记，每项阶段有产物与进入条件，风险有可执行调整。成稿应让独立读者看懂当前方案，删去无关会话记录与工具过程。
- 综述区分文献结论与作者综合判断，主题分类能解释方法差异及研究空缺；技术路线中各模块的输入、输出、依赖和验证能与正文一一对应。删去通用于任何课题的空泛段落，保留本研究的具体条件与取舍。
- 只交付用户要求的最终文件，按当前环境要求保存；测试文件、渲染图和内部检查日志留作内部使用。

## 持续修改同一技能

收到“以后正文改为……”“这个技能的表格改为……”等明确长期偏好时，在本技能上修改。字号、字体、行距、缩进和表线改 `assets/style.json`；章节、段落或论证风格改 `references/writing-patterns.md`；综述与路线组织改 `references/review-and-routes.md`；图表选择改 `references/tables-and-charts.md`；文献图片筛选、引用和解读改 `references/literature-figures.md`；独立运行步骤改 `references/portable-docx.md`；触发范围与流程改本文件；同步检查 `agents/openai.yaml`。

临时单次要求只应用于本次文档。新的长期偏好同时修改配置及相关说明，清理冲突旧值；用一个跨主题短文档检验新风格，继续沿用同一技能名。参考样例仅在用户明确更换样例时替换。在 Work Mode 的 Git 技能目录中，验证后只暂存本技能、提交并推送当前分支；推送失败时保留本地内容并明确报告。
